# GNG - سیستم مدیریت تولید (زیرساخت / پروتوتایپ فاز ۲)

این پروژه لایه‌ی زیرساختی سیستم مدیریت تولید روی دیتابیس `GNG_AI_Dev` است.
هیچ منطق دسترسی/کاربری در نظر گرفته نشده (طبق تصمیم پروژه).

این فرانت‌اند به‌تنهایی به SQL Server وصل نمی‌شود (مرورگر اصلاً نمی‌تواند)؛
برای منو به پروژه‌ی خواهر `gng-mfr-api` وصل می‌شود که در پوشه‌ی کناری همین
مسیر قرار دارد و خودش از `alm.Menu` می‌خواند.

## اجرا (هر دو پروژه لازم است)

۱) اول API را بالا بیاورید: در پوشه‌ی `gng-mfr-api`، فایل `run-api.bat`
   را اجرا کنید. بار اول یک فایل `.env` می‌سازد و از شما می‌خواهد
   `DB_USER`/`DB_PASSWORD` را پر کنید (همان مقادیری که برای اتصال MCP
   دیتابیس `mssql-GNG` دارید)، بعد دوباره اجرا کنید. روی
   `http://localhost:4311` بالا می‌آید.

۲) بعد این فرانت‌اند را بالا بیاورید: `run.bat` را اجرا کنید. روی
   `http://localhost:4400` بالا می‌آید (پورت 4200 برای alm رزرو شده).
   این پورت روی همه‌ی رابط‌های شبکه (0.0.0.0) گوش می‌دهد، یعنی از
   سیستم‌های دیگر هم قابل دسترسی است (بخش «اجرا روی سایر سیستم‌ها» را
   ببینید).

اگر API بالا نباشد، برنامه به‌جای صفحه‌ی خالی، منوی نمونه (mock) را نشان
می‌دهد و در کنسول مرورگر هشدار می‌دهد — یعنی می‌توانید فرانت را مستقل هم
اجرا/دمو کنید.

## اجرا روی سایر سیستم‌ها (بدون نصب چیزی روی آن‌ها)

هر دو پروژه (`gng-mfr-app` و `gng-mfr-api`) فقط باید **یک‌بار، روی همین
سرور** اجرا شوند. کاربرانِ سایر سیستم‌هایی که به این سرور و دیتابیس
`GNG_AI_Dev` دسترسی شبکه‌ای دارند، فقط کافی است در مرورگر خودشان آدرس
این سرور را باز کنند — نیازی به نصب Node/Angular یا کپی‌کردن پروژه روی
سیستم آن‌ها نیست:

```
http://<نام یا IP این کامپیوتر>:4400
```

مثلاً اگر نام این کامپیوتر `GIG001N10355` است:

```
http://GIG001N10355:4400
```

اگر نام کامپیوتر روی شبکه‌ی آن‌ها resolve نشد (خطای «سرور پیدا نشد»)،
به‌جای نام از IP همین سرور استفاده کنید — با دستور `ipconfig` در همین
سرور، مقدار «IPv4 Address» را پیدا کنید (چیزی شبیه `10.0.0.23`).

فرانت‌اند خودش آدرس API را بر همان اساسِ آدرسی که در مرورگر باز شده
حساب می‌کند (`api-config.ts`) — یعنی نیازی به تنظیم دستی روی هر سیستم
نیست. تنها پیش‌نیاز این است که:

- هم `run-api.bat` (در پوشه‌ی `gng-mfr-api`) و هم `run.bat` (همین پوشه)
  روی همین سرور در حال اجرا باقی بمانند (بستن پنجره‌ی PowerShell یعنی
  قطع دسترسی همه).
- فایروال ویندوز روی این سرور اجازه‌ی اتصال ورودی به پورت‌های ۴۴۰۰ و
  ۴۳۱۱ را بدهد (اولین بار که اجرا می‌شود، ویندوز معمولاً خودش یک
  پنجره‌ی تایید «Allow access» نشان می‌دهد — گزینه‌ی شبکه‌ی خصوصی/کاری
  را تایید کنید).
- کاربران سایر سیستم‌ها هم روی همان شبکه‌ی داخلی (LAN) باشند که این
  سرور — این سناریو برای دیتابیس روی سرور، نه اتصال از بیرون سازمان،
  طراحی شده.

## مد رنگی روشن/تاریک

از دکمه‌ی ماه/خورشید در نوار بالا قابل تغییر است؛ انتخاب کاربر در مرورگر
ذخیره می‌شود. در نبود انتخاب قبلی، از تنظیم سیستم‌عامل پیروی می‌کند.

## ساختار

- `src/app/layout` — پوسته‌ی اصلی برنامه: نوار بالا (Topbar، شامل سوییچ
  تم) و منوی درختی کناری (SidebarMenu).
- `src/app/core/services/menu.service.ts` — از `gng-mfr-api` می‌خواند
  (`GET /api/alm/menu`)؛ با خطا/عدم دسترسی به mock سقوط می‌کند.
- `src/app/core/services/theme.service.ts` — سوییچ روشن/تاریک: هم
  استایل PrimeNG را عوض می‌کند هم متغیرهای رنگی GNG را.
- `src/app/features` — هر فیچر/فرم تولید (mfr / generalmfr) این‌جا به‌صورت
  یک پوشه‌ی جدا با lazy-load اضافه می‌شود.
- `src/styles/_theme.scss` — تک‌منبع رنگ/تایپوگرافی برند GNG (روشن +
  تاریک)، برگرفته از `Design_UI_Kit.pdf`. مقادیر hex برآوردی هستند.

## اسکیماهای داده

همه‌ی جدول‌ها و Stored Procedure های سیستم تولید جدید در اسکیمای `mes`
ساخته می‌شوند. قاعده‌ی مدل داده:

- اگر جدولی در `mfr` یا `generalmfr` (نسخه‌ی قبل) معادل دارد، در `mes` با
  همان نام و همان ستون‌ها ساخته می‌شود و ستون‌های تازه به انتهایش اضافه
  می‌شوند؛ تفکیک `mfr` / `generalmfr` در نسخه‌ی جدید وجود ندارد.
- جدول کاملاً تازه فقط وقتی ساخته می‌شود که معادلی نباشد، با همان
  قراردادهای نام‌گذاری (`Id`، `Number`، `Name`، `ParentId`، …).
- همه‌ی جدول‌ها ۱۱ ستون استاندارد پایانی را دارند (`CompanyId` تا
  `RowVersion`).

اسکریپت‌های ساخت در `gng-mfr-api/scripts/mes_*.sql` هستند. اسکیمای `alm`
فقط محیط طراحی/متادیتای توسعه است (ساختار منو از `alm.Menu` خوانده می‌شود).
`mfr` و `generalmfr` مرجع ساختار نسخه‌ی قبل‌اند و برنامه از آن‌ها نمی‌خواند.

## فاز بعد (هنوز انجام نشده)

- اتصال منوهای سطح ۲ (`MenuLevel = 2`, دارای `FormCode`) به فرم‌های واقعی
  (کلیک روی یک آیتم منوی سطح ۲ باید کامپوننت فرم مربوطه را لود کند).
- افزودن مدیریت دسترسی/احراز هویت (عمداً در این فاز کنار گذاشته شده).
- جابه‌جایی `API_BASE_URL` (در `src/app/core/api-config.ts`) به یک فایل
  environment مجزا برای build پروداکشن.
